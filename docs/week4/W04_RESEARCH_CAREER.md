## GA2 — Manuscript-ready METHODS & ETHICS draft, no invented results

**Working title:** *A Rights-Gated, Tamper-Evident Workflow for Synthetic Behavioral Benchmark Reproducibility: Design Protocol and Adversarial Acceptance Criteria.*

### Abstract — planned-methods paper (no empirical conclusions)

Reproducible behavioral prediction requires more than deterministic pseudorandom seeds: data authorization, participant-aware validation, selection-independent evaluation and verifiable artifact lineage must be jointly evaluated. We describe a proposed three-component research-software architecture in which (P1) an internally generated, wholly fictional repeated-measures task is benchmarked using participant-disjoint nested cross-validation; (P13) a canonical hash-linked provenance chain records source, split, model specification and reported result; and (P25) a deny-by-default dataset-rights evaluator constrains execution, aggregate sharing and imports. The protocol prespecifies a majority/dummy baseline, balanced accuracy, a sealed holdout, controlled perturbations, integrity-negative cases, concurrent-state tests and exact environment capture. Cryptographic hash agreement is not treated as authentication, and an original synthetic generator is not represented as participant research. This document specifies verification targets; it does not assert that production integration, independent replication, security accreditation or rights clearance has been completed.

### Proposed methods, versioned

The generator creates fictional trials for groups called participants, but no real-person records are involved. The existing W03 manifest holds `generator_seed=73`, `split_seed=42`, `n_participants=36`, `trials_per_participant=12`, `outer_folds=3`, `inner_folds=2` and only prespecified pre-outcome predictors `difficulty` and `stimulus_condition`. W03 nested group CV selects logistic regularization from `C ∈ {0.1, 1.0}` *inside* training data, with dummy comparator; evaluation uses balanced accuracy. These are verified design contracts from inspected W03 source, **not newly executed W04 findings**. The held-out group partition and per-fold preprocessing must be independently rechecked at the W04 review SHA. Primary method justification: Cawley & Talbot (2010), Varoquaux et al. (2017), Varoquaux (2018), Kriegeskorte et al. (2009).

For binary labels with two observed classes, `balanced_accuracy = 0.5 * (TP/(TP+FN) + TN/(TN+FP))`. An all-one-class predictor on a two-class test sample yields balanced accuracy exactly 0.5; this analytic negative/null oracle is not an expected population result for every trained model. If a class is absent, the report must explicitly disclose metric convention/exclusion instead of hiding undefined rates. Prespecified seed **robustness** would repeat the complete group-partition protocol across independent, predeclared generator seeds (for example 73, 74, 75), with all outcomes reported and no best-seed selection; this has **not been run**. A feature-ablation protocol would compare fixed pre-response predictors versus a single predeclared subset under identical participant splits and inner selection; changing predictors requires a new contract version rather than secretly modifying W03's frozen manifest.

The source/rights manifest is verified before scheduling; participant-level indices are checked for disjointness, complete group membership and pre-response feature timing. Each immutable run is joined to a four-node content-addressed provenance graph. The W04 envelope binds run ID, expected legacy digest and policy metadata and exposes JSON export/verify/import endpoints. Policy decisions are recorded in a separate metadata-only SQLite ledger with sequence and hash links; deliberate revocation blocks new permitted actions, but deletion, true consent governance and cryptographic external anchoring are **out of scope**. No human data are stored or downloaded.

## GA7 — Skeptical referee report + preregistered replication critique

**Referee recommendation: Major revision / not ready for public release.** Positives: boundaries between P1 prediction evaluation, P13 hash-linked lineage and P25 rights audit are unusually explicit; hostile fixtures and an analytical baseline are aligned with best-practice methodological concerns.

**Major objection 1 (methodology):** Only one original fictional data generator, fixed 3/2-fold group CV and frozen feature set. The 0.5 balanced-accuracy dummy oracle under two classes is a useful software check, not an estimate of scientific accuracy or evidence of model benefit. Three dependent outer folds do not yield reliable frequentist population confidence intervals. **Falsification:** predeclare multiple seeds/groups; compute per-participant confidence uncertainty with clear exchangeability assumptions, display all seed-level outcomes; add negative permutation control and known leaky split comparator, using the same data and no test-set selection.

**Major objection 2 (external validity):** "participant" is a fictional group label. Group K-fold blocks exact group overlap but not source-site, household, session and temporal leakage. **Falsification:** inject same-participant cross-split duplication, session proxies, near-duplicates and future-response features; prohibit data exploration after sealed holdout opening.

**Major objection 3 (rights):** P25 has a static original-synthetic allowlist and typed metadata, not a legal contract interpreter. Reviewer string is not independent proof and revoked consent doesn't retrospectively erase stored derivatives. **Falsification:** third-party apparent Creative Commons metadata without verified license must deny; expired and withdrawn must deny; multi-role cross-tenant denial and signed dataset contract future milestones.

**Major objection 4 (custody):** Local SHA root can be rewritten along with the data. **Falsification:** tamper with one node, order, model version, report and entire DB; single-node tests detect local mutations; coordinated rehash passes unless external signer/anchor is used. Explicitly log that limitation in findings.

**Major objection 5 (reliability/UX):** SQLite CAS jobs are **state records**, not resumable model computations. UI semantic structure is not a browser audit. **Falsification:** kill worker midway through model fit, restart from safe checkpoint, demonstrate bitwise aggregate agreement; keyboard/screen-reader walkthrough; load test under bounded concurrency; backups/restore and permissions test.

**Replication handoff:** Pin actual base W03 commit and proposed W04 SHA; attest source file SHA256 and pip freeze/OS; execute full W03 group generator → API → P13 verify → P25 authorize → SQLite audit, then deny an unauthorized dataset/role and mutate an envelope. Compare expected run identity/result separately by interpreter; untested scenarios remain FAILED GATE, not implied success. A reviewer independent of the code author must sign off before release.
