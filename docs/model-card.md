## Model summary and intended users

This experimental workbench is designed for computational psychology and neuroscience **methodology students, research assistants, ML engineers and reproducibility reviewers**. It demonstrates how to evaluate **fictional trial correctness** from two pre-response task conditions using transparent baselines. The intent is to test the *engineering and evaluation protocol*, not to learn about real cognition.

**Label:** `correct`, a binary 0/1 invented outcome for an internally generated two-choice task.

**Permitted predictors:** `difficulty` (unitless in [0,1]) and `stimulus_condition` (left/right). These variables are available before the synthetic response. The project rejects using patient identity or participant/session/trial IDs as predictors, as well as `correct`, `response`, `response_time_ms`, timestamps, future observations or outcome-derived participant aggregates.

**Candidate estimators (implementation, unverified):**
1. Training-only `DummyClassifier(strategy="prior")`.
2. Training-only `StandardScaler` and `OneHotEncoder` inside a `ColumnTransformer` / `Pipeline` followed by `LogisticRegression(solver="lbfgs", C=1.0, max_iter=1000, random_state=42)`.

There is **no pretrained model checkpoint or fitted production model**. The above describes source code paths, not observed training success.

## Data, rights and subject independence

- Only synthetic records generated by the repository's own seeded generator are currently enabled in [registry.json](../data/registry.json). Public dataset candidates are **disabled metadata** and have NOT been ingested or cleared for use.
- Source `rights_basis=synthetic-original` is not permission for third-party datasets. Source-code licensing does not establish human dataset rights. The synthetic data model has no medical patients, human experimental participants or institutional ethics approval.
- Unit of attempted generalization: **previously unseen fictional participant**, not row-level trial holdouts. Participant ID grouping must be disjoint across training, validation and test. The same `session-01` label across fictional participants is not itself a global group identifier.
- v1 config prespecifies **24 fictional participants, 20 trials each** with generator seed 73 and split seed 42 (design parameters only; **not observed dataset or score counts**).
- Five training-only `GroupKFold` folds select a model on average valid training-CV balanced accuracy. Validation subjects are diagnostic; untouched test subjects are scored once per **prespecified** candidate, after model selection, with **no** fitting or tuning on test data. Training-only scaling and categorical encoding are part of fold-specific pipelines.

## Appropriate / prohibited use

**Intended:** software-development demonstration of rights checks, synthetic-data structure, train-only preprocessing, group-respecting validation, reproducibility manifests, basic ML comparison and failure reporting.

**Not permitted or supported:** medical decision-making, diagnosis, prognosis, therapy selection, health screening, decisions about individuals, causal inference about psychology/neuroscience, real-world discrimination or fairness claims, population-level effect size estimation, publication of model performance without independent verification, deployment as a human-research collection platform, uploading actual participant/clinical/PHI records, or using real data without an explicit rights/privacy/ethics review and separate authorization.

## Risks, failure modes and limitations

- **Simulation mismatch:** The generator has arbitrary success probabilities, artificial abilities and latency; it is not fitted to human observations and contains no neurophysiological measurements.
- **Dependence:** Trial rows from a participant are correlated and must not be treated as independent replicates in inference or bootstrap intervals.
- **Leakage:** Including post-response `response` or `response_time_ms` would expose information causally unavailable at prediction time; pre-response features must be allowlisted before model fitting.
- **Preprocessing leakage:** Fitting encoder/scaler outside training groups produces optimistic scores; the source uses fold-scoped sklearn pipelines, subject to actual runtime verification.
- **Selection bias:** Repeating seeds or tuning based on held-out test scores invalidates the frozen evaluation contract. All candidate and threshold changes must be prespecified and versioned.
- **Class imbalance:** Group folds can be single-class; scoring must explicitly fail as undefined, not silently stratify by outcome or invent finite metrics.
- **Dependency drift:** A source-only, broad optional scikit-learn range is not a lockfile. Future verified CI artifacts must record Python, sklearn, numpy, dependencies, source SHA, config digest and fold digests; reproducibility across environments remains unproven.
- **Security & rights:** The loader and config validator are engineering boundaries, not hardened untrusted-data sandboxes or legal certifications.
